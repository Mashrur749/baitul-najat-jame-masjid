# Baitul Najat Jame Masjid — brand & marketing system

A website and a marketing-asset factory that share one brand definition.
Change a value in `brand/tokens.json`, rebuild, and the site *and* every poster,
social post and print file move together.

## The one rule

**Never write a literal hex, font stack, or artboard size into a template.**
Everything comes from `brand/tokens.json` via generated CSS variables and Tailwind
utilities. If you need a value that doesn't exist, add it to the tokens file — do not
inline it. This is the whole reason the system holds together.

## Layout

```
brand/
  tokens.json        ← SINGLE SOURCE OF TRUTH. Colour, type, spacing, motif, artboards.
  BRAND.md           ← Strategy: positioning, voice, hard rules, reference log.
  references/        ← Drop reference images here. See its README for naming.
  fonts/fonts.css    ← Generated by `npm run fonts`. Base64. Gitignored.
src/                 ← 11ty website
  _includes/macros/brand.njk   ← SHARED macro library (also used by assets-src/)
  _data/brand.js               ← exposes tokens.json to site templates
assets-src/          ← Marketing asset templates (Nunjucks) + content/*.json
scripts/
  tokens-to-css.mjs  ← tokens.json → src/css/tokens.generated.css (@theme block)
  render.mjs         ← content JSON + template → dist/assets/*.png|pdf via Chromium
  fetch-fonts.mjs    ← vendors webfonts so renders are reproducible
  shoot.mjs          ← screenshots a built page for visual review
```

## Commands

```bash
npm run dev       # 11ty dev server with live reload
npm run build     # assets + tokens + css + site → _site/ (full production build)
npm run build:site # site only, skips asset rendering (faster while iterating on pages)
npm run assets    # tokens → css → render every asset in assets-src/content/
npm run render X  # render one asset (assets-src/content/X.json)
npm run fonts     # re-vendor webfonts after changing type tokens
node scripts/render.mjs X --format pdf   # print-ready vector output
node scripts/shoot.mjs _site/index.html dist/screens/home.png
```

## Creating a marketing asset

1. Pick an artboard from `tokens.artboard` (or add one).
2. Write `assets-src/content/<name>.json` — `template`, `artboard`, `data`.
3. Reuse an existing template if the shape fits. Only add a `.njk` for a genuinely new layout.
4. `npm run assets`
5. **Read the PNG back and critique it.** Non-negotiable — see below.

## The visual feedback loop — do this every time

Rendered output lands at a predictable path (`dist/assets/<name>.png`), specifically so
it can be read straight back with the Read tool. Generating an asset and *not* looking at
it is how broken layouts ship.

```
render → Read the PNG → critique honestly → fix → re-render → Read again
```

Things this loop catches that reading the code does not: collapsed flex layouts, text
overflowing the artboard, dead space that reads as a mistake, illegible small type,
a script falling back to the wrong font, motif competing with body copy.

**Known trap:** Tailwind scans template files at build time. If you add a template *and*
build CSS in the same step, the scanner runs before the file exists and every utility is
silently missing — the render succeeds and looks like an unstyled dump. Always
`npm run css:assets` (or `npm run assets`, which chains it) *after* writing templates.

**Second trap:** macros build class names dynamically (`text-{{ tone }}`), which static
scanning cannot see. Any such class must be listed in the `@source inline(...)` block in
`assets-src/assets.css` and `src/css/app.css`.

## Content and language

- Bangla and Arabic are first-class. Wrap them in `<span lang="bn">` / `<span lang="ar" dir="rtl">`
  and the correct face plus line-height applies automatically from tokens.
- Use the `bilingual()` and `arabic()` macros rather than hand-rolling.
- **Never** transform, gradient, rotate, or overlay text on Quranic text or the Bismillah.
- Prayer times live in `src/_data/prayer.json` — a placeholder. Anything the committee
  edits weekly should end up somewhere they can edit without a deploy.

## Brand guardrails

Read `brand/BRAND.md` §2 before making visual decisions. The load-bearing ones:

- Geometry, not photography. No images of congregants without written consent.
- Brass (`--color-brass`) is an accent — never body text, never links. It fails WCAG AA
  on paper at body size. `tokens.colorRules` states the limits.
- Warm paper (`--color-paper`), never pure white.
- One message per asset. These are read at 3 metres or thumbed past in a second.

## Current state

not decisions. Run `/brand-extract` once reference images are in `brand/references/` to
